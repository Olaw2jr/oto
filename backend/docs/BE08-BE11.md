# BE-08 to BE-11 implementation review

## BE-08
Added catalogue search (escaped case-insensitive substring), ranked discovery
based on review counts and average ratings, and social activity discovery
from users a reader follows. Pagination uses offset and a bounded limit.
Future work: full-text indexed search, author filters, recommendation
ranking, abuse controls and cached materialised recommendation feeds.

## BE-09
Added a snapshot endpoint for current library and listening progress and
optimistic-lock progress writes. This is a first sync contract, not yet an
offline-first reconciliation protocol. Missing: durable idempotency keys,
server-side monotonically increasing revisions, delta cursors/tombstones,
batch submission, device leases, retry queue and conflict coverage.
The current progress endpoint's version uses timestamp microseconds and
should not be treated as robust optimistic concurrency across clocks.
An existing user progress API still permits unconditional writes, so route
all production clients through one validated sync policy before rollout.
A bounded import runner exists but has no scheduler or job persistence.

## BE-10
Added `app/api/OtoApiClient.ts`, covering remote search, discovery,
book details, library and sync snapshots. It is not wired into the
existing React Native screens or composition root. Token persistence and
refresh are injected. Do not save refresh tokens in AsyncStorage.

## BE-11
Added request IDs, basic response headers and minimal route tests.
Remaining: migrations on a live DB, security integration tests, CORS policy,
request quotas, OpenTelemetry, metrics, dependency audit, provider egress
policy, bearer-token redaction, key management, health/readiness checks,
deployment environment manifests, release automation and load tests.

## Verification
Tests were authored but not run against a running PostgreSQL + Neo4j stack
in this session. The PR should remain draft until all stacked foundations
are tested and CI is green.
